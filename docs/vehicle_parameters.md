# 차량 파라미터 요청 목록

| 항목 | 내용 |
|---|---|
| 상태 | v0.5 (설계 문서 v0.6 기준) |
| 관련 문서 | [설계 문서](design.md) |

시뮬레이터에 차량을 입력하는 데 필요한 데이터 목록입니다. 차량 빌더(설계 문서 §5), 동역학(§6~§8), 실제 환경 모델(§10), 전기 시스템(§12), 검증(§13)에서 씁니다.

## 작성 방법

- **CAD가 가장 먼저입니다 (§0).** 형상, 질량 특성, 서스펜션 기하, 센서 위치는 CAD 어셈블리에서 나옵니다. 아래 표에서 비고에 **CAD**라고 표시된 항목은 CAD를 주면 따로 채우지 않아도 됩니다. 실측값이 있으면 CAD 값을 덮어씁니다.
- **값** 칸을 채워 주세요. 모르면 비워 두거나 "모름"이라고 써 주세요. 모르는 값은 대표값으로 시작합니다.
- **데이터시트 PDF, CAD 질량 특성 리포트, 측정 원본 파일이 있으면 수치를 옮겨 적지 말고 파일을 공유**해 주세요. 필요한 값은 제가 추출합니다.
- 표 형태 데이터(곡선, 맵)는 단위가 적힌 헤더를 붙인 CSV가 가장 좋습니다. 예: `soc, temp_c, ocv_v`
- 앞/뒤 또는 코너별로 다르면 모두 적어 주세요.
- 시뮬레이터는 특정 실차에 묶이지 않습니다. 설계 중인 차라면 설계값을 적으면 됩니다.

**우선순위**

| 표시 | 의미 |
|---|---|
| ★★★ | 필수. 차를 굴리는 데(M1) 필요 |
| ★★ | 권장. 정확도에 중요 |
| ★ | 선택. 고충실도 모델(L3, Level B)이나 DIL 체감용 |

## 0. CAD 데이터 (가장 먼저)

차량 빌더(설계 문서 §5)의 입력입니다. 빌더(`ui/builder/index.html`, 사용법은 [build.md](build.md)의 "차량 빌더")에 STEP을 올리면 아래 §2, §3의 **CAD** 항목(질량, 무게중심, 관성, 비현가 질량, 휠 회전 관성, 휠베이스, 트레드, 타이어 반경)과 서스펜션 하드포인트, 센서 위치가 `vehicle/builder.yaml`로 저장되어 `vehicle.yaml`을 덮어씁니다.

| 항목 | 우선 | 비고 | 값 |
|---|---|---|---|
| 차량 전체 어셈블리 STEP 파일 | ★★★ | AP214 또는 AP242 권장. 서스펜션, 파워트레인, 배터리, 드라이버 마네킹 포함하면 좋음 | |
| 사용하는 CAD 프로그램 | ★ | STEP 내보내기 가능 확인됨 (설계 문서 Q-26). 프로그램 이름은 참고용 | |
| 부품 재질(밀도) 지정 여부 | ★★ | 지정되어 있음 (Q-26). STEP에 재질이 안 실려 오면 부품별 밀도를 빌더에서 지정 | 있음 |
| CAD 프로그램의 질량 특성 리포트 | ★★ | 부품 또는 서브어셈블리별 질량·무게중심·관성. 있으면 형상 계산보다 우선 | |
| CAD 원점과 축 방향 | ★★★ | 예: 원점은 앞차축 중심 지면, X 후방, Z 위 | |
| 서스펜션 하드포인트 | ★★★ | 서스펜션 형식과 하드포인트는 STEP을 넣은 뒤 빌더에서 설정 (설계 문서 §5.5). CAD에 이름 있는 점을 미리 만들어 두면 자동 매칭되어 더 빠름 | |
| 센서 장착 좌표계 (선택) | ★★ | CAD에 `SENSOR_<이름>` 좌표계를 만들어 두면 자동으로 센서 위치가 됨. 없으면 3D 편집기에서 찍으면 됨 | |
| 부품 이름 규칙 (선택) | ★ | 예: `FL_UPRIGHT*`. 있으면 바디 매핑이 자동으로 됨 | |

**시뮬레이터를 만들고 돌리는 데는 필요 없습니다.** 시뮬레이터는 특정 실차와 무관하고(설계 문서 Q-25), 실측은 시뮬레이션 결과나 외란 크기가 실제와 얼마나 맞는지 확인할 때만 씁니다 (설계 문서 §13.1). 별도 데이터로거가 없어도, VCU/BMS가 기록한 CAN 로그면 충분합니다. 외란 측정 방법은 아래 §19에 정리했습니다.

| 항목 | 우선 | 비고 | 값 |
|---|---|---|---|
| 기록 방식 | ★ | 데이터로거(MoTeC, AiM 등) 또는 VCU/BMS의 CAN 로그 | |
| 파일 형식 | ★ | CSV, MDF4, CAN 원시 로그 + DBC 등 | |
| 채널 목록과 샘플링 주기 | ★ | 목록 파일을 그대로 공유해 주시면 됩니다 | |
| 샘플 로그 1개 | ★ | 상관성 기능을 이 파일로 먼저 만듭니다 | |

**있으면 좋은 채널** (있는 만큼)

- 운전 입력: 핸들각, APPS (2채널), 브레이크 압력 (앞 / 뒤)
- 차량 운동: IMU (ax, ay, az, 롤·피치·요 레이트), GPS (위치, 속도, 헤딩), 휠속 4개
- 파워트레인: 모터별 토크 명령과 추정 토크, 모터 속도, 상전류, DC 전압·전류, SoC, 셀 최소/최대 전압
- 온도: 모터, 인버터, 셀 최고/평균, 냉각수
- 서스펜션: 댐퍼 포텐셔미터
- 제어 내부값: TV yaw moment 명령, TC 개입 플래그 등

**있으면 좋은 시험 데이터**

| 시험 | 식별·검증할 수 있는 것 |
|---|---|
| 정상 원선회 (여러 속도) | understeer gradient, 타이어 횡방향 스케일 |
| 스텝 조향 | 과도 응답, 요 관성, 타이어 이완 |
| 직진 가속 | 종방향 그립, 파워트레인 |
| 급제동 | 브레이크 이득, 종방향 그립 |
| 코스트다운 | Cd·A, 구름저항 |
| 펄스 방전 (정지 상태 또는 주행 중) | 배터리 R0, RC |
| 트랙 연속 주행 (엔듀런스형) | 에너지, 열, 전체 상관성 |

## 15. CAN 통신

가상 CAN(설계 문서 §12.2, M8)에 필요합니다. 버스와 DBC는 UI의 CAN 네트워크 편집기에서 직접 등록하므로, 여기서는 있는 파일만 알려 주시면 됩니다.

| 항목 | 우선 | 비고 | 값 |
|---|---|---|---|
| CAN 버스 구성 (버스 개수, 각 버스에 붙은 ECU) | ★★ | 간단한 그림이나 표로 충분 | |
| 버스별 속도와 규격 | ★★ | CAN 2.0 / CAN FD, 500 kbit/s / 1 Mbit/s 등 | |
| DBC 파일 | ★★ | 메시지 ID, 주기, 신호 정의. 없으면 편집기에서 새로 만들 수 있음 | |
| 인버터·BMS의 CAN 프로토콜 문서 | ★★ | 제조사 제공 문서 | |
| 메시지 타임아웃 처리 규칙 | ★ | 어떤 메시지가 끊기면 VCU가 어떻게 반응하는지 | |

### 18.1 `vehicle.sensors` 쓰는 법 (M6)

`vehicle.yaml`(또는 빌더가 쓴 `builder.yaml`)의 `sensors:` 목록에 한 줄씩 적습니다. 출력 신호는 `sens.<name>.<채널>`입니다. 예제 차량 [vehicle.yaml](../templates/projects/example_fs_ev/vehicle/vehicle.yaml)에 12개가 있습니다.

```yaml
sensors:
  - {name: imu, type: imu, position: [0.0, 0.0, 0.25], orientation_deg: [0, 0, 0], rate_hz: 500, anti_alias_hz: 100,
     accel: {noise_density: 0.0015, bias: 0.2}, gyro: {bias_instability: 1.5e-5},
     vibration: [{motor: fl, order: 8, amplitude: 0.8, axis: z}]}
  - {name: ws_fl, type: wheel_speed, wheel: fl, teeth: 36}
  - {name: apps, type: pedal, pedal: throttle, ch1_v: [0.5, 4.5], ch2_v: [4.5, 0.5],
     faults: [{channel: ch2, type: open, at_s: 12.0}]}
```

**공통 항목**

| 항목 | 단위 | 내용 |
|---|---|---|
| `name` | | 신호 이름에 쓰임 (영문·숫자·_) |
| `type` | | 아래 표의 종류 |
| `position` | m | 무게중심 아래 지면 기준 [x 앞, y 왼쪽, z 위] (빌더가 찍음) |
| `orientation_deg` | ° | 센서 축의 [롤, 피치, 요] (센서 x축이 차 앞이면 0, 0, 0) |
| `rate_hz` | Hz | 출력 주기 (물리 스텝 1 ms의 배수로 맞춤) |
| `signal` | | 재는 버스 신호 (temperature, signal 종류는 필수; 다른 종류는 기본값을 바꿀 때) |
| `faults` | | `[{channel, type, at_s, until_s, value}]`, type: offset · stuck · open(0) · short(전원) · value · noise · scale. `channel`을 빼면 모든 채널 |

**채널 오차 항목** (채널 이름 아래, 또는 IMU는 `accel:`·`gyro:` 아래에 공통으로)

| 항목 | 단위 | 데이터시트 이름 | 켜지는 조건 |
|---|---|---|---|
| `scale_error` | 비율 | 감도 오차 (1σ) | `realism.variation: real` |
| `bias` | 측정 단위 | 영점 오프셋 (1σ) | `realism.variation: real` |
| `noise_density` | 단위/√Hz | noise density (가속도: µg/√Hz × 9.81e-6) | `realism.sensors: real` |
| `bias_instability` | 측정 단위 | bias instability (Allan 최저점의 1/0.664) | `realism.sensors: real` |
| `bias_tau_s` | s | 드리프트 상관시간 (기본 100) | |
| `random_walk` | 단위·√Hz | rate random walk | |
| `bandwidth_hz` | Hz | 출력 대역폭 (1차) | |
| `latency_s` | s | 출력 지연 | |
| `resolution` | 측정 단위 | 분해능 (ADC LSB, 데이터 형식) | |
| `range` | [최소, 최대] | 측정 범위 (포화) | |

**종류별**

| type | 채널 (단위) | 기본 주기 | 종류별 항목 |
|---|---|---|---|
| `imu` | ax, ay, az (m/s², 비력: 정지 시 az = +9.81), gx, gy, gz (rad/s) | 500 Hz | `anti_alias_hz`(샘플링 전 2차 필터, 0이면 없음), `misalignment_deg`(개체별 장착 오차 1σ, 기본 0.5), `vibration: [{motor, order, amplitude, axis}]` |
| `accelerometer` / `gyro` | IMU의 절반 | 500 Hz | IMU와 같음 |
| `wheel_speed` | omega (rad/s), pulses | 200 Hz | `wheel`(fl…, 없으면 위치로), `teeth`(48), `timeout_s`(0.1), `timer_resolution_s`(1e-6), `tooth_error_deg`(0.05, 개체 편차), `directional`(true) |
| `pedal` | ch1, ch2 (V) | 1 kHz | `pedal`(throttle), `ch1_v`·`ch2_v`: [0 % 전압, 100 % 전압] |
| `brake_pressure` | pressure (bar) | 1 kHz | |
| `steering_angle` | angle (rad, 핸들각) | 100 Hz | |
| `gnss` | x, y (m), speed (m/s), heading (rad), valid | 10 Hz | `position_sigma_m`(0.02), `speed_sigma_mps`, `heading_sigma_deg`, `latency_s`(0.05), `drift_m`, `outages_per_min`, `outage_s` |
| `current` / `voltage` | value (A / V) | 1 kHz | 기본 신호 `bat.current` / `bat.voltage` |
| `temperature` | value (°C) | 10 Hz | `signal` 필수 (예: `pt.motor.fl.temp`), `time_constant_s`(2) |
| `suspension_travel` | travel (m, 범프 +) | 500 Hz | `wheel` (L3에서만) |
| `signal` | value | 100 Hz | `signal` 필수: 아무 버스 신호나 같은 오차 체인으로 |

**VCU 설정** (`control/vcu.yaml`, 센서가 있을 때)

| 항목 | 기본 | 내용 |
|---|---|---|
| `use_sensors` | true | false면 드라이버 페달과 참 속도 사용 |
| `apps.min_v`, `apps.max_v` | 0.2, 4.8 | 이 범위 밖은 단선·단락 |
| `apps.max_deviation` | 0.10 | 두 채널 차이 한계 (FSAE: 10 %p) |
| `apps.fault_time_s` | 0.10 | 이 시간 넘게 이어지면 토크 차단 (FSAE: 100 ms) |
| `apps.deadband` | 0.02 | 페달 양 끝 데드밴드 |
| `bspc.brake_bar` | 10 | "브레이크 작동" 압력 |
| `bspc.apps_on`, `bspc.apps_off` | 0.25, 0.05 | BSPC 차단 / 해제 페달 위치 |
| `speed_estimator.tau_s` | 0.1 | 바퀴가 미끄러지지 않을 때 휠속 쪽으로 당기는 시정수 |
| `speed_estimator.slip_tau_s` | 3.0 | 미끄러질 때(바퀴 차이 5 % 초과 또는 큰 가감속) |
| `speed_estimator.free_accel_mps2` | 2.0 | 이보다 큰 가감속은 미끄러짐으로 봄 |

## 19. 외란 측정 (선택)

외란 크기를 실제와 맞추기 위한 측정입니다 (설계 문서 §10.7, §13.4). 시뮬레이터 사용에는 필요 없습니다. 센서, 모터, 트랙은 다음 차에서도 그대로 쓰는 경우가 많으므로, 지금 있는 차에서 잰 값을 설계 중인 차의 시뮬레이션에도 그대로 쓸 수 있습니다. 실차의 센서와 CAN 로그만으로 충분합니다.

| 측정 | 방법 | 얻는 것 | 소요 |
|---|---|---|---|
| 정지 상태 센서 기록 | 차를 평지에 세우고 전원만 켠 상태로 10~30분 기록. 가능하면 HV 켠 상태(인버터 대기)와 끈 상태를 각각 | 센서 노이즈 밀도, 바이어스, 바이어스 불안정성 (Allan variance), 전기적 결합 노이즈 | 30분 |
| 모터 회전 진동 기록 | 차를 띄우고(잭업) 모터를 여러 속도로 돌리며 IMU 기록 | 모터 차수 진동 스펙트럼 | 30분 |
| 목표 트랙 주행 기록 | 일정 속도로 직선·코너 주행하며 IMU, 휠속, 서스펜션 변위 기록 | 노면 진동 PSD, 노면 거칠기 등급 추정 | 1회 주행 |
| 코스트다운 | 직선에서 일정 속도부터 동력을 끊고 감속 기록 (왕복) | Cd·A, 구름저항 | 30분 |
| 펄스 방전 | 정지 또는 주행 중 출력을 계단식으로 바꾸며 팩 전압·전류 기록 | 배터리 R0, RC | 30분 |
| LV 전압 기록 | 펌프·팬 기동, 고출력 가속 중 LV 버스 전압 기록 | LV 전압 강하, DC-DC 응답 | 주행 중 함께 |
| CAN 버스 기록 | 주행 중 전체 버스 로그 | 실제 버스 부하, 메시지 주기 편차(클록 드리프트·지터) | 주행 중 함께 |
| 날씨 기록 | 측정 당일 기온, 기압, 습도, 바람, 노면 온도 | 위 측정들의 환경 조건 | — |
